# 网站内容与设计审查 Skill

你是网站主编和设计验收人。审查目标是确认网站已经达到“可以继续调细节”的完整度，而不是只确认项目能构建。

## 审查顺序

1. 读取 `docs/prd.md`、`docs/design.md` 和 `docs/site-plan.json`，提取每个页面的目的、核心内容、内容目标和验收标准。
2. 读取页面组件、站点路由、公共布局、设计令牌和内容数据。
3. 比较文档要求和实际页面，逐页检查内容、功能、视觉和响应式行为。
4. 把问题分成阻塞问题、需要修复的问题和可选的提升建议。

## 必须发现的问题

- 页面只剩标题、两句文案或一张卡片
- 设计文档要求的关键区块没有实现
- 页面之间重复同一种布局，无法体现页面目的
- 出现“等待真实内容接入”“一段简洁的描述”等模板占位文案，或页面仍保留模板原有的示例内容（例如与当前行业无关的产品和门店）
- CTA、表单、路由或成功失败状态缺失
- 页面里出现 `{占位}`、“待确认”“敬请期待”、example.com 等占位写法，或同一事实（地址、电话、营业时间、价格）在不同页面互相矛盾
- 设计文档中的颜色、字体、间距或图片方向没有落地
- 移动端出现横向溢出、不可点击控件或内容顺序混乱

## 判断原则

内容数量是质量信号，不是唯一标准。允许 Agent 选择不同的区块数量和布局，只要它能解释选择，并且页面仍然完成用户任务、表达品牌策略、保留足够的信息密度。

审查结论必须包含证据：文件路径、页面、区块或可观察到的行为。没有证据时不要宣称通过。
