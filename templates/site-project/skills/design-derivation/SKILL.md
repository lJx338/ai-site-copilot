# 网站设计推导 Skill

你是产品设计总监。读取 `docs/prd.md` 后，生成一份真正能指导建站的 `docs/design.md`。设计文档既要表达设计师的判断，也要为代码 Agent 提供足够明确的实现线索。

## 推导顺序

按照下面的因果关系写设计决策：

```text
业务定位 + 用户 + 使用场景
→ 品牌个性和目标情绪
→ 视觉方向和差异化策略
→ 页面叙事和信息层级
→ 区块的布局、内容和交互
→ 颜色、字体、图片、动效和响应式规则
```

每个视觉决定都要说明它解决什么业务问题。不要只列颜色名称或形容词。

## design.md 必须包含

### 0. 设计依据

说明从 PRD 推导出的视觉方向、情绪目标和关键设计策略。

### 1. 品牌个性定位

包含核心定位、目标情绪、差异化策略、设计决策摘要和首屏第一感觉。

### 2. 色彩系统

提供语义化颜色、使用场景、文字对比关系和成功、错误、警告等功能颜色。颜色应能转换成 `design/tokens.json` 和 CSS 变量。

### 3. 布局决策

说明整体布局、Hero 方案、留白、对齐、视觉层级、转化触点和功能页面的状态流转。

### 4. 字体排版

说明标题、正文、辅助文字、数字和价格的层级、大小、行高和使用场景。

### 5. 交互动效

说明触发条件、动效属性、时长、缓动和移动端降级方式。动效不能遮挡表单和主要任务。

### 6. 区块与视觉处理映射

这是最重要的一节。每个页面区块必须包含：

- 商业目的
- 用户需要理解的信息
- 推荐布局
- 内容字段和推荐内容量
- 图片或素材方向
- 主要行动入口
- 可自由发挥的视觉变体

区块可以使用不同的布局和风格，但页面目的和核心信息不能丢失。

### 7. 图像规范

定义 Hero、品牌故事、产品、门店、人物和工艺图片的主题、情绪、构图、色调、去重规则和素材缺失时的处理方式。

### 8. 文案调性

定义语气、句式、标题和 CTA 示例、内容长度、事实约束、占位符规则和合规限制。没有真实事实时直接写可信的示例内容（具体到数字、名称和地址），禁止使用 `{占位描述}`、“待确认”“敬请期待”这类占位写法。

### 9. 多端适配

定义断点、桌面端、平板和移动端的布局差异、导航行为、图片策略、表单行为和性能处理。

## 页面内容蓝图

每个页面都要单独写一份内容蓝图。它至少包含：

- 页面目的
- 页面叙事顺序
- 必须出现的区块
- 推荐出现的区块
- 每个区块的内容目标和推荐数量
- 页面需要的图片类型
- 页面主要 CTA
- 交互状态
- 验收标准

例如菜单页不能只写“使用产品卡片”，而要说明分类、招牌推荐、产品字段、产品数量建议、季节内容和底部转化入口。设计可以选择目录型、杂志型或画廊型表达，但必须保留完整浏览能力。

## 事实和创作空间

把内容分成三类：

- 已确认事实：可以直接使用
- 示例内容：用户没有提供的事实，由你补全成可信、具体、全站一致的内容，并在“内容事实表”里集中列出
- 创作空间：允许 Agent 根据品牌策略自行决定

设计文档不能把页面固定成唯一布局。它应该规定目标、信息、质量和边界，让 Agent 在这些边界内选择更好的表达方式。

## 图像

网站必须使用真实感的图片（照片或 AI 生成的写实图），不能用 CSS 色块或示意 SVG 代替照片。设计文档要写一行「图像风格：……」统一全站的光线、色调、构图和质感；每个页面蓝图写清楚配图位置和画面内容。页面用 `SiteImage` 组件声明图片，系统会从图库搜索或用 AI 生成。
